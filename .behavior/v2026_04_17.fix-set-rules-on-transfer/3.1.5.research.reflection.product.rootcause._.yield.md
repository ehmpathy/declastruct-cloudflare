# root cause analysis: declarative cloudflare redirect rules

## what is the symptom?

**observable problem**: users who transfer domains to cloudflare must manually configure redirect rules via dashboard

**how it manifests**:
- each new domain requires 5-10 minutes of dashboard clicks
- domains get inconsistent redirect policies
- some domains lack HTTP→HTTPS redirect (security/trust issue)
- some domains lack root→www redirect (SEO split)
- no audit trail of who changed what

**when it occurs**: every time a domain is transferred to cloudflare and needs redirect rules

---

## 5 whys tree

### branch 1: manual dashboard work

1. **why?** → users spend 5-10 minutes per domain in dashboard
2. **why?** → redirect rules can only be set via dashboard or API
3. **why?** → declastruct-cloudflare doesn't support redirect rules
4. **why?** → we built DNS records first, haven't added rules yet
5. **why?** → **[root cause]** redirect rules were not in initial scope of declastruct-cloudflare

### branch 2: inconsistent redirect policies

1. **why?** → some domains have HTTP→HTTPS, others don't
2. **why?** → each domain is configured manually, separately
3. **why?** → no shared configuration template
4. **why?** → humans forget steps, make mistakes, copy-paste wrong
5. **why?** → **[root cause]** manual processes don't scale consistently

### branch 3: SEO and security issues

1. **why?** → users hit mixed content warnings or SEO splits
2. **why?** → domains lack proper redirect rules
3. **why?** → redirect rules are tedious to set up
4. **why?** → no declarative way to enforce them
5. **why?** → **[root cause]** cloudflare rules require imperative API or manual UI

---

## root cause summary

| layer | issue | is root cause? |
|-------|-------|----------------|
| symptom | manual dashboard work | no |
| process | no shared template | no |
| tools | declastruct doesn't support rules | **yes** |
| design | cloudflare requires imperative config | yes (external, can't fix) |

**primary root cause**: declastruct-cloudflare lacks redirect rule support

**secondary root cause**: cloudflare's API requires imperative operations (we can't change this, but we can abstract it)

---

## recommendation

### address root cause: add redirect rule support to declastruct-cloudflare

**fix**:
- add `DeclaredCloudflareDomainRuleRedirect` domain object
- add get/set/del operations for redirect rules
- add preset specs for common patterns (HTTP→HTTPS, root→www)
- integrate with declastruct provider

**why this addresses root cause**:
- users declare redirect rules in code (no dashboard)
- rules are version-controlled (audit trail)
- presets ensure consistency (same policy everywhere)
- declastruct plan/apply workflow fits extant mental model

### we cannot fix the deeper root cause (cloudflare design)

cloudflare's API requires imperative operations (POST/PUT/DELETE). we cannot change their API design.

but we can **abstract** it:
- declastruct converts declarative intent to imperative API calls
- users think declaratively, declastruct executes imperatively
- this is the same pattern we use for DNS records

---

## validation

this feature addresses the root cause because:

1. **eliminates dashboard clicks** — rules in code, not UI
2. **ensures consistency** — presets encode best practices
3. **provides audit trail** — git history tracks changes
4. **scales to many domains** — same resources file pattern as DNS

the wish is to control redirect rules declaratively. this feature directly addresses that root cause.
