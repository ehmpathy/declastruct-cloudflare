# blueprint: declarative cloudflare domain redirect rules

## summary

add declarative control over cloudflare domain redirect rules via:
- `DeclaredCloudflareDomainRuleRedirect` domain entity
- `DeclaredCloudflareDomainRuleRedirectSpec` spec literal
- preset specs: `RULE_REDIRECT_SPEC_HTTP_TO_HTTPS`, `RULE_REDIRECT_SPEC_ROOT_TO_WWW`
- get/set/del operations with findsert/upsert semantics
- DAO integration for declastruct provider

follows extant DNS record patterns exactly, per 3.1.3.research.internal.product.code.prod._.yield.md patterns 1-8.

## api translation

cloudflare rulesets API to domain operations:

| cloudflare API | domain operation |
|----------------|------------------|
| `GET /zones/{zone_id}/rulesets/phases/http_request_dynamic_redirect/entrypoint` | getAllDomainRuleRedirects |
| `PUT /zones/{zone_id}/rulesets/{ruleset_id}` | setDomainRuleRedirect, delDomainRuleRedirect |

note: cloudflare requires PUT of entire ruleset — individual rule operations are not supported.

## key decisions

### slug→description translation

`slug` in domain object translates to `description` in cloudflare API. this enables:
- unique identification by slug (description is searchable)
- developer-friendly names (kebab-case slug vs freeform description)

### ruleset PUT semantics

per 3.1.1.research.external.product.flagged._.yield.md [5], cloudflare advises updating "the entire ruleset in a single operation" to avoid concurrent update conflicts. this informs our PUT-based approach:
- get all rules for zone
- filter/modify as needed
- PUT entire ruleset back
- document in readme: "declastruct manages the entire ruleset"

### preset expressions

per 3.1.1.research.external.product.flagged._.yield.md [6][7], expressions must use `http.host` for hostname match — `cf.zone.name` is NOT available.

HTTP→HTTPS: `(http.request.uri.scheme eq "http")`
root→www: `(not starts_with(http.host, "www."))`

### custom rules over managed features

per 3.1.1.research.external.product.flagged._.yield.md [1][2], cloudflare offers "Always Use HTTPS" as a toggle. we use custom rules instead because:
- declastruct manages all state declaratively
- unified approach for both redirect types
- visible in same ruleset for audit

### rate limits

per 3.1.1.research.external.product.flagged._.yield.md [4], cloudflare API allows 1,200 requests per 5 minutes. declastruct usage (1 GET + 1 PUT per zone) is well under this limit — no special rate limit logic needed.
