# blackbox criteria: declarative cloudflare domain redirect rules

## usecase.1 = declare redirect rules on domains

```
given a resources file with domain zones and redirect rules
  when declastruct plan is run
    then a plan shows redirect rules to be created per zone
      sothat users preview changes before apply

  when declastruct apply is run
    then redirect rules are created in cloudflare
      sothat domains have the declared behavior
    then the plan shows no changes on subsequent runs
      sothat users know the state is converged

given a resources file with preset specs
  when RULE_REDIRECT_SPEC_HTTP_TO_HTTPS is declared
    then http requests to the domain redirect to https
      sothat users always get secure connections
    then query strings are preserved in the redirect
      sothat links with parameters continue to work

  when RULE_REDIRECT_SPEC_ROOT_TO_WWW is declared
    then apex domain requests redirect to www subdomain
      sothat SEO consolidates on canonical URL
    then query strings are preserved in the redirect
      sothat links with parameters continue to work
```

## usecase.2 = custom redirect rules

```
given a resources file with custom DeclaredCloudflareDomainRuleRedirectSpec
  when a custom expression is declared
    then requests that match the expression are redirected per parameters
      sothat users can implement arbitrary redirect logic

  when targetUrl uses a static value
    then all matches redirect to that exact URL
      sothat simple redirects work without expressions

  when targetUrl uses an expression
    then the redirect URL is computed per request
      sothat dynamic redirects work (e.g., path preservation)
```

## usecase.3 = rule identity and idempotency

```
given a redirect rule with a slug
  when the same slug is declared twice in the same zone
    then declastruct rejects the duplicate
      sothat users avoid accidental conflicts

  when the rule already exists in cloudflare with the same slug
    then declastruct updates the rule rather than creates a duplicate
      sothat re-runs are idempotent

  when a rule is removed from the resources file
    then declastruct deletes it from cloudflare
      sothat the declared state matches the remote state
```

## usecase.4 = error surface

```
given an invalid expression in the spec
  when declastruct apply is run
    then cloudflare rejects the rule with an error message
    then declastruct surfaces the cloudflare error to the user
      sothat users can fix their expression syntax

given a zone that does not exist
  when a redirect rule references that zone
    then declastruct fails with a clear error
      sothat users know to create the zone first
```
