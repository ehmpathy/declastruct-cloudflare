# audience reflection: declarative cloudflare redirect rules

## who is the audience?

### primary: devops engineers who manage multiple domains

**role**: engineers who manage cloudflare infrastructure for an organization with 5+ domains

**context**:
- responsible for consistent security posture across all domains
- transfer domains to cloudflare for DNS, SSL, and CDN
- currently set up redirect rules manually per domain via dashboard
- git-ops mindset — want all infra in version control

**constraints**:
- time-limited — can't click through dashboard for every domain
- must maintain consistency — same redirect policy everywhere
- need audit trail — "who changed what when"

### secondary: platform engineers who build internal tools

**role**: engineers who build abstractions for product teams

**context**:
- create workflows for product teams to deploy new domains
- want declarative config that non-devops can use
- integrate cloudflare setup into broader IaC pipelines

**constraints**:
- must be composable with other tools (terraform, pulumi, etc)
- need clear error messages for debug

### tertiary: security auditors who review configurations

**role**: auditors who verify security compliance

**context**:
- audit redirect policies in security reviews
- verify all domains enforce HTTPS
- check for misconfigurations

**constraints**:
- need visibility into what rules exist
- want diffs when rules change

## how will they experience it?

### touchpoints

1. **discover**: find feature in declastruct-cloudflare docs or release notes
2. **adopt**: add `DeclaredCloudflareDomainRuleRedirect` to resources file
3. **plan**: run `declastruct plan` — see rules to be created
4. **apply**: run `declastruct apply` — rules created in cloudflare
5. **verify**: check cloudflare dashboard or curl to confirm redirects work
6. **maintain**: git diffs show rule changes over time

### friction points

| phase | friction | mitigation |
|-------|----------|------------|
| adopt | learn new domain object | presets eliminate need for expression knowledge |
| adopt | remember field names | TypeScript autocomplete guides |
| plan | unclear output | clear diff output like DNS records |
| verify | need to check dashboard | document how to test via curl |
| maintain | drift detection | declastruct handles via plan diff |

### smooth experience

```
day 1: "I need HTTP→HTTPS on all our domains"
├─ find RULE_REDIRECT_SPEC_HTTP_TO_HTTPS preset
├─ add 3 lines to resources file per domain
├─ run `declastruct plan` — see "+6 redirect rules"
├─ run `declastruct apply` — done in 30 seconds
└─ curl verifies redirects work

day 30: "new domain transferred to cloudflare"
├─ copy-paste block from extant domain
├─ run plan + apply
└─ 2 minutes, no dashboard
```
